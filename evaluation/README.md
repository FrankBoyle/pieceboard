# Button evaluation

The [separately authored set](independent-review.md) has a preserved [first result at runtime `149ba97`](results/independent-149ba97.json). Its 40 scored scenarios contained 28 defective controls; seven additional scenarios were explicitly unscorable diagnostics. The run found **16 true positives, 3 false positives, and 12 false negatives: 84.2% precision and 57.1% recall**. All 47 fixtures ran without setup errors. All 225 eligible generated source associations and 80 requested representative previews succeeded, which does not establish real-project accuracy or image readability.

Labels were frozen in `8ab0e0d` before scoring. A second software agent authored them without reading the detector implementation, but did read documentation exposing earlier behavior; there was no independent human label review or representative sampling. The artifact records frozen hashes, runtime/runner hashes, actual browser, contexts, and every prediction/error. It is image-free. The detector and runner were unchanged during that first run.

Misses included repeated deviations, opacity, blur, and requirements known only to the fixture author: a wrong majority, a two-control reference, and a tie. False positives included two intentional exceptions without machine-readable variant hints. A tool cannot infer those authored design requirements reliably from frequency alone; projects can provide approved references, explicit variants, and review decisions. The score is below the plan's provisional goals.

Subsequent repeated-deviation and opacity/filter work was informed by this result. This set is therefore a regression set for those changes, **not a fresh held-out accuracy estimate**. The original labels and result remain unchanged. Use `npm run evaluate:independent` to replay the current runtime; use a checkout at `149ba97` to reproduce the recorded detector. Set `UI_SHEET_BROWSER` if using an installed compatible browser. The runner uses bounded sequential captures and a temporary loopback-only server. Fresh independently authored data and external review remain necessary for later accuracy claims.

The [post-tuning replay at `6acfb2c`](results/regression-6acfb2c.json) found **21 true positives, 3 false positives, and 7 false negatives: 87.5% precision and 75.0% recall** on the same 40 scored cases. All 47 fixtures completed, including the seven diagnostics. It used Playwright's bundled Chromium `156.0.8078.4`, whereas the first recorded run used Edge `156.0.4314.58`; this is not a controlled same-browser estimate of improvement. Repeated radius deviations, opacity and blur were now found. Remaining errors involve wrong-majority/tied/undersampled design requirements and intentional unmarked exceptions, which require approved references or explicit review context. The provisional targets are still unmet, and these known-case results cannot replace fresh labels.

An earlier replay attempt with the local Edge installation stopped after six completed cases when browser cleanup exceeded its 15-second deadline; no complete result was written. The matching bundled-browser run then completed against the unchanged runtime. Use the bundled Playwright browser for the documented default workflow; a custom executable can fail independently of the detector.

Run `npm run evaluate:buttons` for a small, labeled synthetic development set, or `npm run --silent evaluate:buttons -- --json` for per-case JSON. Labels refer to individual button indexes within each case. The scorer counts individual controls, including all controls sharing a reported outlier appearance.

The cases cover seeded differences, explicit variants, disabled controls, ties, approved baselines, a deliberately unmarked variation, a majority that is wrong, and an undersampled case. Some are intentionally beyond the detector's current capabilities; false positives and false negatives remain visible.

[Public-site field notes](field-notes.md) record an exploratory Bootstrap check and a separate public application/source scan, including limitations and a source-context issue found during testing. They are not independently labeled evaluations.

To repeat the six hand-selected source-link checks against the public Microsoft Edge demo, install Playwright Chromium and run `npm run evaluate:public-source`. Set `UI_SHEET_BROWSER` to a compatible browser path if using an existing installation. The command downloads a pinned HTML/CSS source snapshot into a temporary folder, fetches the live page, renders it in isolated browser sessions, and deletes the temporary source afterward. It does not click or submit the demo, but the page runs its JavaScript and makes normal network requests. The JSON output compares the live and pinned HTML hashes and checks the selected source records, DOM elements, and presence of source-linked previews. It also reports whether each preview's PNG bytes match a fresh capture as a diagnostic; different bytes do not necessarily mean different pixels, and this diagnostic does not determine the association result. A changed or unavailable upstream page can make the command fail. The capture and DOM inspection are separate requests, so the page could change between them. Six hand-selected cases do not establish general accuracy or verify the deployed CSS, JavaScript, or complete repository revision.

This is a hand-authored development set created with knowledge of the current algorithm. It is not held out, independently labeled, representative of other projects, or a measure of screenshot quality and source-link accuracy. Its scores should not be used as a product-wide accuracy claim. Independent examples and a separate held-out evaluation are still needed.

[`browser-holdout.json`](browser-holdout.json) is a separate set of 24 synthetic browser scenarios and expected button labels prepared after the detector at revision `fe560ff`, before its first score on this set. It includes intentional variants, unobservable or excluded states, unsupported visual properties, small samples, and cases where frequency conflicts with the specified intent. The same implementer wrote these labels with knowledge of the algorithm; they are not independent or representative. Freeze this file before scoring and report failures rather than changing labels or tuning to the score. A separate, independently labeled evaluation is still needed.

Run `npm run evaluate:browser` after installing Playwright Chromium, or use `npm run --silent evaluate:browser -- --json` for per-case, image-free results. Set `UI_SHEET_BROWSER` to a compatible installed browser if needed. The command builds temporary local pages, starts a loopback-only server, captures them, and removes its temporary files. It does not interact with the controls. It scores individual buttons and separately reports source matches and preview counts.

The [first recorded run](results/browser-fe560ff.json), using Chromium 156 on 2026-11-04 UTC, found 8 true positives, 2 false positives, and 5 false negatives: 80.0% precision and 61.5% recall across 24 cases containing 13 labeled positive controls. The missed controls included a gradient, italic text, an undersampled pair, and a wrong majority. The false positives were the minority in the wrong-majority case and an intentional unmarked variation. All 67 eligible controls matched their generated source lines, and all 39 requested representative previews were captured. A repeat on the same browser installation reproduced the predictions, source-match counts, and preview counts. These checks use small static pages with unique IDs and do not establish real-world source-link accuracy or screenshot readability. These results apply only to this set and detector revision. Subsequent gradient and text-style changes were informed by these findings, so this set is no longer held out for evaluating those changes; new independent labels are needed for that purpose.
